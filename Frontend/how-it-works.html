Reference

Everything the contract does, in plain terms.

BugBounty.sol handles the whole lifecycle — creating a bounty, filing a report, and paying it out. This page walks through each function and state so nothing on the app screen is a surprise.

Contract functions

What each call actually does

createBounty(title, description)payable · organization

Opens a new bounty. The ETH sent with the transaction becomes the reward and is held by the contract until the bounty is resolved.

submitReport(id, reportHash)researcher

Attaches a report hash to an open bounty and moves it into the Submitted state. Only the hash lives on-chain — the write-up itself stays wherever you host it (IPFS, a document, etc.).

resolveBounty(id, accepted)organization only

Accepts or rejects the submitted report. Accepting transfers the locked reward to the researcher in the same transaction; rejecting closes the bounty without paying out.

getBounty(id)view · anyone

Reads back a bounty's title, description, reward, organization, researcher, report hash and status. This is what the live bounty board calls to render every card.

Status

A bounty is always in exactly one state

Open

Reward is locked. Waiting for a researcher to submit a report.

→

Submitted

A report hash has been filed. Waiting on the organization's decision.

→

Resolved

Accepted and paid, or rejected. Either way, the bounty is closed.

Before you connect

What the app checks for you

✓

MetaMask installed

The app detects window.ethereum before doing anything else.

✓

Network is Sepolia

If you're on another network, the app requests a switch to chain ID 11155111 before connecting.

✓

Account & network changes

Switching accounts or networks in MetaMask is detected automatically and reflected in the app.

✓

Contract address configured

The deployed BugBounty address is set once in the app's script before it can read or write anything.
